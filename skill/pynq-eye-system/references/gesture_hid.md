# 手势跟踪 滚动与 CH9329

管线为相机 → 掌检测 → 裁剪 → 关键点 → 跟踪几何 → 手势状态机 → 输出门控 → UART CH9329 → 主机页面。定位问题先记录各阶段，不能把所有无响应归因于模型。

## 固定交互规则

捏合解锁。其余四指收拢，食指伸直向上滚、向掌心弯曲向下滚。中间姿态停止输出，捏合高度变化不额外产生滚动。离手保留解锁模式，但没有新鲜姿态时不发送旧动作；回到画面首帧静默，避免跳动。

当前 `hand_tracker.py`、`gesture_control.py` 来自不同最终修订批次，统一入口在 `src/ps/gesture/`。画面无关键点连线，内部仍计算 21 个关键点。

## 弯曲时丢手

闭拳可能导致掌检测失败。保持本帧关键点置信度和几何检查，不以周期掌检测的单次空结果立即丢弃有效跟踪。真实四角点参与变换，避免每次旋转重新包围轴对齐框造成 ROI 膨胀。低置信度仅作一次有界裁剪重试，失败时不能回放旧关键点。

原修订回放 10/12→12/12，空白帧拒绝输出；真人弯曲/伸直验收通过。新增改动执行统一 `test`，再覆盖多人、遮挡、旋转、长间隔与离开返回。

## 有识别却不滚动

按顺序检查：报告 ready、交互模式、控制输出开关、姿态方向、结果时间戳、HID 服务日志、UART 查询、USB connected、主机焦点与滚动区域。PMODA 配置为 9600 8N1，不套用其他 USB 串口路径的 115200 默认值。

`ch9329-pmoda.conf` 调整过本项目结果时限为 6 秒，以匹配历史慢推理；这不允许重复发送旧手势。性能改善后若改阈值，必须验证掉帧时停止、重入静默与限速，不仅测试连续正样本。

实物验证前鼠标指向报告文字区，刷新网页后重新解锁；伸直与弯曲各保持约 8–15 秒并记录动作方向、是否丢手、端到端时延。自动单元测试不发送 HID，不能替代 USB 到主机的闭环检查。

## 输入、判别和验收证据

输入为本次故障图像/回放、帧时间戳、当前 tracker/controller 摘要，以及输出门控和 HID 日志。画面和问卷按原项目的数据保存范围处理。

| 证据 | 定位方向 |
|---|---|
| 掌检测空，但本帧关键点有效 | 检查周期重检是否误清有效跟踪 |
| ROI 随旋转持续变大 | 检查真实四角点是否被反复轴对齐包围 |
| 新关键点置信度低于 0.8 | 检查裁剪；当前实现仅允许一次受限重试，不能降阈值复用旧姿态 |
| 姿态方向正确但无 UART 输出 | 查报告就绪、模式、时间门限、过期/去重门控 |
| UART 输出成功但主机不滚动 | 查 USB connected、主机窗口焦点和滚动区域 |

修改后执行统一 `test`，同时检查空白、多人、低置信度、长间隔与反向切换。失败时回退本次跟踪或控制器改动，保留故障帧和日志，不从旧整套发布目录覆盖后端。

完成条件：本次故障样本恢复、负例停止输出、29 项既有回归结果有记录，现场方向/重入反馈与离线回放分开。仅离线条件满足时明确“现场待验证”。
