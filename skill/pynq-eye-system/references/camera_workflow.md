# 双摄像机 网页与按键业务

输入是已确认角色的两只 USB 摄像机、十题问卷固件、当前模型与有效服务。输出为一次检查的图像、结果 JSON、叠加图、HTML 和状态记录。

## 操作流程

1. 读取 `/api/state`，记录检查号、`busy`、`workflow_state`、`report_ready`、相机与推理状态。保留已有报告。
2. 说“小幻小幻”，听到“我在”后按 BTN0 开始问卷；回答完成后进入眼部采集。问卷中止不强行继续相机流程。
3. BTN1 拍照；画面进入待确认后，BTN3 提交确认并分析。页面确认框随当前检查状态同步，新检查不能继承旧确认。
4. 报告就绪后启用手势交互。BTN2 在任何已支持的活动阶段取消问卷、关闭眼部相机并结束进程，不允许浏览器续连自动恢复。

网页 `/api/action` 和 `/api/lease` 的写请求受 CSRF 与状态条件保护。不要绕过图像确认或伪造待确认状态。按钮服务通过已有客户端提供 token，读状态不需要 token。

## 相机问题定位

USB 曾从旧 HUB 的端口映射变更到手势 1.3、眼部 1.4；这些是历史证据，不是永久设备号。以当前 `camera_switch/camera_roles.json`、by-path/sysfs 和实物图像确认角色，不能只依据 `/dev/video0` 或 `/dev/video2`。

预览使用 MJPEG、最新帧队列和独立推理进程。检查 `camera_active`、`frame_fresh`、`frame_seq`、`preview_fps` 是否变化；图像流顺畅不意味着模型帧率同样高。不要让采集端回读自己正在写入的 multiprocessing pipe。

读帧失败时依次检查枚举、USB 速率、占用、角色配置和 worker 错误。不能仅凭枚举成功宣称全流程可用。若需要更换 HUB 或供电，待设备稳定后重新确认角色。

## 维护与验证

当前源在 `src/ps/camera_web/`、按钮在 `src/ps/shared/button_service.py`。历史页面测试、采集测试和设备状态测试可通过 `locate` 查找 `web_source` 来源中的 `test_service.py`、`test_fast_preview.py`、`test_device_status.py`，需恢复对应目录后运行。

修改停止逻辑后，保持浏览器打开并观察 BTN2 之后至少一次续连：相机不恢复、相关子进程退出、旧报告仍可定位。修改 BTN3 后验证待确认、忙碌、无照片和长按四种状态，错误请求不能启动重复分析。

## 联调失败与结束判据

问卷超时、取消或中止时验证不进入采集；相机被占用时先确定持有进程，避免盲目重启所有服务。BTN2 在问卷、预览和分析三类场景分别验证：业务状态停止、相关进程/cgroup 退出、视频设备句柄释放、网页续连不重开，且能再次通过 BTN0 开始。仅有页面按钮变灰不足以证明停止。

完成记录须关联检查号、图像、模型版本、问卷题目版本、各状态时间和异常。若语音或 OLED 只有离线预览，则将相应实物验收标记为未执行；不要据其他模块成功填为通过。跨外设回归使用 [验收矩阵](acceptance.md)。
