# 验证矩阵与移植边界

## 自动验证

- `capabilities`：所有能力资源存在、参考资料可定位。
- `verify`：当前入口和历史归档哈希；研究文档修订后的哈希与原始哈希分别保留。
- `test`：29 项手势控制和跟踪回归，覆盖捏合、方向、失手、旋转与裁剪。
- `python skill/pynq-eye-system/tests/test_project.py`：技能工具自身的根目录定位、路径约束、诊断、发布基线和拒绝覆盖。
- 模型、网页、语音、OLED 与共享资源的原测试通过 `locate` 找到后恢复原布局运行；部分依赖板端环境或模拟模块，应按测试前置条件选择，不能把跳过当作通过。

## 现场完整闭环

| 范围 | 触发与观察 | 通过条件 |
|---|---|---|
| 启动与外设 | 核对六服务、owner、UART、I2C | 版本匹配、无异常重载；各输出分别验证 |
| 语音 | 唤醒、三类答案及重复相同答案 | 播放正确、答案读到、读后清零 |
| 按键 | BTN0 问卷、BTN1 拍照、BTN3 分析 | 状态迁移正确，长按不重复提交 |
| 停止 | 活动中按 BTN2，网页保持打开 | 相机及任务退出，续连不自动恢复 |
| 报告与 OLED | 新图像分析完成 | 检查号、图像/模型摘要、报告及实屏一致 |
| 手势 | 捏合、伸直、弯曲、离开 10 秒后返回 | 方向正确，弯曲无持续漏识别，离手停输出、返回不跳动 |
| 性能 | 相同输入 warm/cold、现场并发负载 | 分项和端到端分别记录；不混淆 FPS 与推理速度 |
| 回退 | 在保存备份的测试环境恢复 | 版本和启用状态恢复，旧报告仍可用 |

每次记录硬件/代码/权重哈希、时间来源、图像条件、服务日志和实物反馈。板端时钟曾落后于实际年份，实验日期需由可信时钟和启动标识交叉确认。

## 迁移到其他题目或板卡

可复用的是单一 owner/共享租约、按检查号组织状态、分层计时、模型黄金参考、动作新鲜度门控和有界恢复流程。管脚、地址、I2C 上拉、固件词条、模型类别、阈值和 UI 文案属于本项目配置，必须按目标系统重新定义。

技能依赖配套工程与真实硬件。离线测试不能证明电气连接、声音、实屏和主机滚动正常；缺少训练集不能从已有权重反推出完整训练复现。新平台验证须重新走上述矩阵，不沿用本项目的数值结论。

## 本版离线入口

```sh
python -B skill/pynq-eye-system/scripts/project.py capabilities
python -B skill/pynq-eye-system/scripts/project.py verify
python -B skill/pynq-eye-system/scripts/project.py test
python -B skill/pynq-eye-system/tests/test_project.py
```

技能入口按 8 类工程流程组织，能力索引保留 14 项功能，两个计数表示不同维度。调用 `release` 只生成计划；`build` 不加 `--execute` 只生成命令。阅读技能后不会自动安装或启动板卡任务。

修改技能时另外检查本地 Markdown 链接和 `SKILL.md` 的 name/description；工具验证不能替代实际使用判断。此次整包校验和离线测试见工程 `docs/preparation.md`，仅代表记录中的版本。


本文件的历史工程路径按 [协作版资源与归档说明](../../../docs/resources.md) 访问。协作版默认 verify 不要求完整归档，工具测试不要求模型或板卡。

## 眼部照片门控

无眼图：保持待确认、可重拍、无报告和手势启动；清晰眼图：进入原分析；缺失组件：技术错误且不分类；BTN3 忙碌时显示进度。运行 `python -B sim/test_eye_presence.py -v` 和 `npm run test:ui`，另记录授权照片回归与实物 BTN3 反馈，不能把默认跳过的照片测试写成通过。
