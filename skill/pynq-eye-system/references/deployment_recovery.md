# 一致发布与故障回退

## 先生成可复查发布物

统一 `release` 读取 `assets/deployment_map.json`，对每个源文件与技能基线摘要比对，拒绝目标路径重复或未知版本。加 `--output /new/release.tgz` 生成 `rootfs/` 与 `deployment_manifest.json`；此操作不安装板卡。

映射明确选择最终 worker、控制器、跟踪器，避免旧掌检测包内 worker 覆盖新版。运行库、权重、bit/hwh、owner、驱动及服务配置同时列出。文件模式、运行账号和依赖仍以实际服务环境核对。

发布包是可审查的覆盖载荷，不是 SD 镜像。现有 `camera_switch/`、摄像机角色、网页基础 unit、系统库、字体、SSH 配置和数据目录必须在目标环境验证。全新板卡先完成 PYNQ 环境与这些依赖，不通过“解压成功”宣称部署完成。

## 已配置板卡的部署流程

1. 采集服务状态、完整 `systemctl cat`、文件哈希、FPGA generation、检查号、模型和报告状态。忙碌或仍需保存的检查先结束或保留，不清空报告。
2. 创建唯一备份批次，保存所有拟覆盖文件、unit/drop-in、启用状态和文件属性，记录哪些目标原本不存在。备份验证成功后才进入替换。
3. 纯软件修改只停相关消费者，不重载 FPGA。硬件修改须等待 DMA idle、释放共享租约、停止消费者，再由唯一 owner 加载同批 bit/hwh。
4. 在同一文件系统暂存并校验，再原子替换选定文件；更新配置后执行 daemon-reload。恢复启动顺序为 owner→palm→网页→按钮/HID/OLED，并按实际依赖调整。
5. 比对发布清单、服务状态、网页接口与模块输出；确认已有报告仍可访问，未修改硬件时 generation 和下载次数不变。
6. 失败时停止继续覆盖，恢复本批次备份及原启用状态；验证后再重试。不能重复调用旧版首次部署脚本绕过“备份已存在”的保护。

旧部署脚本可用于理解已验证的事务顺序，不直接视为任意版本通用安装器。通过 `locate` 查询 `shared_fpga/deploy_shared.sh`、`tools/palm_pl_20261028/deploy_palm.py`、`tools/gesture_latency_20261028/deploy_latency.py`、`tools/gesture_reliability_20261028/deploy_board.py`；原布局恢复后按其参数和基线使用。

## 回退边界

跟踪可靠性、ncnn、掌检测 PL 是逐次叠加版本。优先回退当前改动的最小范围；整体回退遵循最新软件→此前软件→硬件的逆序，并核对各脚本实际备份。不要恢复旧 worker 而留下不兼容的新后端。

连接失败先检查地址、网络和服务；I2C 阻塞、DMA 未 idle、原始哈希不匹配时停止自动重试并保留现场。排障记录用问题、证据、修改和结果组织，不把推测当成已确认根因。

## 本次变更的交付格式

输入包括期望的当前板端摘要、选定新文件、明确的目标映射、可恢复备份和验收矩阵。每个覆盖文件保存源路径、目标路径、原摘要、新摘要、文件属性和是否原本存在；新增文件的回退动作必须与覆盖文件区分。

纯 tracker 修订只回退对应文件；模型更新需要配套权重和元数据；硬件变更需要匹配 bit/hwh 与运行接口。启动顺序最终以 `systemctl cat` 合并依赖为准，不机械套用历史列表。

发布准备以清单与载荷一致为通过，安装验收另以文件摘要、服务/API、旧报告保留和本次功能实测为通过。安装失败仅对本批次做有界恢复，回退后再采集状态；缺备份、基线不明或 DMA 未 idle 时不得继续覆盖。未实际部署时交付状态应写“已生成发布物，未安装”。


本文件的历史工程路径按 [协作版资源与归档说明](../../../docs/resources.md) 访问。协作版默认 verify 不要求完整归档，工具测试不要求模型或板卡。
