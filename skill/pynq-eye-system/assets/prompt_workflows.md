# 可复用提示词工作流

使用方法：选择一个任务段落，填入真实输入位置后交给协作工具或研究成员。每次只解决一个明确问题；已有证据足够时直接引用，不要求重复运行。以下是整理后的工作模板，不冒充原始聊天记录。

## A. 从算法到软硬件划分

适用：已有可运行 CPU 参考，需要选择 FPGA 加速部分。

> 任务：为所附算法和目标器件提出软硬件划分。输入为算法源码、真实输入形状、逐层计时、通信方式、可用资源及 CPU 黄金参考。先区分已测事实与推测；按计算时间、传输/布局转换开销、复用率、资源预算列候选。保留收益不足的 CPU 算子，不把单层加速比直接扩展为整网加速比。输出每个候选的输入输出契约、资源估计依据、最小实现范围及新增验证项。缺实际测量时给出采样方法，不编写性能数字。对没有变化的既有验证只引用文件与日期。

失败条件：没有同口径 CPU 数据、忽略传输、直接要求全模型上 PL。项目来源：掌检测全层替换开销较大，最终选择六层；见性能报告。

## B. 从实现报告定位瓶颈

适用：已有 HLS/Vivado 原始报告及本次源码。

> 任务：依据这些报告解释资源和时序瓶颈。先说明每份报告对应的工具版本、器件、源码版本和阶段；分别列出 HLS 估计、Routed 时序、资源及 DRC/CDC。对关键路径找出起终点、逻辑与布线贡献；对 II 区分目标值和达到值。提出一项最小改动及预计影响，不将估计时钟当作实际可运行频率。输出原报告引用、待修改位置、风险、应新增的验证；没有重建时保留原版本数字，不声称优化已成功。

失败条件：只读取摘要截图、混用版本、忽略约束缺失。项目来源：HLS 核与整网/RPC计时、综合估计与 Routed 频率的区分。

## C. 多进程共享 FPGA 与外设故障

适用：多个服务共享 Overlay、DMA、I2C 或 UART。

> 任务：根据已提供的服务状态、generation、租约、DMA idle、错误日志和版本清单定位故障。先识别唯一硬件配置所有者及消费者。按供电接线→协议/地址→软件环境→所有权→业务状态分层排除。禁止通过消费者反复下载位流解决不明问题；DMA 未确认 idle 时不释放仍被使用的缓冲区。输出证据对应的原因、最小恢复步骤及停止条件；现有授权范围内执行，未授权的外部写入只准备可复查方案。设备不存在或离线时明确哪些结论未验证。

失败条件：不同代际资源混用、未知 MMIO 地址、无法确认任务是否正在运行。项目来源：共享 Overlay 冲突、语音供电和 OLED 接线异常。

## D. 动作已识别但输出迟滞或丢失

适用：摄像机→模型→状态机→HID/网页链路。

> 任务：使用本帧序号和单调时间戳追踪一次动作。分别分析采集、DETECT/TRACK、裁剪、模型、状态机确认、输出门控和主机响应。无新鲜输入时不重发旧动作；短时丢手是否保持交互模式按用户需求处理。通过同一段回放区分检测失败、ROI失效、置信度不足与输出门控，提出最小修改。输出复现步骤、前后有效帧数、方向正确性和新增边界测试；预览 FPS 不作为推理吞吐，模型耗时不作为端到端延迟。

失败条件：没有帧标识、只观察 LED 或页面滚动、把旧结果当作新结果。项目来源：弯曲时漏检与保留解锁状态的修订。
